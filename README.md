# portscan

Встраиваемый Go-пакет для TCP Connect-сканирования IPv4, IPv6 и DNS-имён.
Требуемая версия Go: **1.25.5**. Только стандартная библиотека; внешних зависимостей нет.
Пакет не содержит CLI, HTTP-сервера, БД или брокера сообщений.

## Использование

Положите пакет в свой Go-модуль и замените путь импорта `portscan` на путь своего репозитория
(также обновите строку `module` в `go.mod`). В текущем модуле импорт выглядит так:

```go
package main

import (
    "context"
    "fmt"
    "log"
    "time"

    "portscan"
)

func main() {
    scanner, err := portscan.New(
        portscan.WithConcurrency(100),
        portscan.WithConnectTimeout(500*time.Millisecond),
    )
    if err != nil {
        log.Fatal(err)
    }

    ctx, cancel := context.WithTimeout(context.Background(), 30*time.Second)
    defer cancel() // Обязательно при досрочном прекращении чтения.

    results, err := scanner.Scan(ctx,
        []string{"127.0.0.1", "::1", "localhost"},
        portscan.Union(portscan.Range(8000, 8010), portscan.List(22, 80, 443)),
    )
    if err != nil {
        log.Fatal(err)
    }
    for result := range results {
        fmt.Printf("host=%s ip=%s port=%d state=%s duration=%s err=%v\n",
            result.Host, result.IP, result.Port, result.State, result.Duration, result.Err)
    }
    if err := ctx.Err(); err != nil {
        log.Printf("сканирование остановлено: %v", err)
    }
}
```

## Публичный API

- `New(...Option) (*Scanner, error)` создаёт сканер. Значения по умолчанию: 100 подключений, 500 мс.
- `WithConcurrency(int)` устанавливает положительный общий лимит подключений **на экземпляр сканера**, включая одновременные вызовы `Scan`.
- `WithConnectTimeout(time.Duration)` задаёт положительный таймаут каждого подключения и отдельно каждого DNS-запроса. Родительский context может сократить это время.
- `List(...int) Ports`, `Range(first, last int) Ports`, `Union(...Ports) Ports` описывают набор портов. Диапазоны включают обе границы. Значения `Ports` неизменяемы и пригодны для повторного конкурентного использования. Ошибки описания портов возвращает `Scan`.
- `(*Scanner).Scan(context.Context, []string, Ports) (<-chan Result, error)` синхронно проверяет параметры и запускает потоковую обработку. Сканер создаётся только через `New`; нулевое значение отклоняется.
- `Result` содержит `Host string`, `IP net.IP`, `Port uint16`, `State State`, `Duration time.Duration`, `Err error`.
- `State` — строковый тип с константами `Open`, `Closed`, `Timeout`, `Unreachable`, `Canceled`, `Error`.

Нулевой/отрицательный лимит или таймаут, nil option/context, пустые цели и порты,
порты вне 1..65535 и обратные диапазоны возвращают ошибку до запуска работы.
Результирующий канал при ошибке запуска равен nil. Уже отменённый context возвращает `ctx.Err()`.

## Цели и DNS

Пробелы по краям имени удаляются. IPv4/IPv6 нормализуются; IPv4-mapped IPv6
сводится к IPv4. DNS-имена приводятся к нижнему регистру, завершающая точка удаляется.
Повторы нормализованных целей и портов удаляются с сохранением первого вхождения.
Разные DNS-имена и явный IP остаются разными целями, даже если указывают на один адрес.

Принимаются IP-литералы без квадратных скобок и ASCII DNS-имена с метками из букв,
цифр и дефиса (1..63 символа, без дефиса на краях; максимум 253 символа всего).
Односоставные имена, например `localhost`, допустимы. IDN передаются в punycode.
Пустые имена, адрес с портом, CIDR, scoped IPv6 (`%zone`), некорректные IP и DNS-имена
отклоняются. Строка только из цифр и точек должна быть корректным IP.

Каждое уникальное DNS-имя разрешается один раз на вызов `Scan` системным Go resolver.
Проверяются **все** уникальные полученные IP, по одному результату на IP и порт.
DNS выполняется последовательно в производителе заданий; подключения к уже
разрешённым целям продолжаются параллельно. Для ошибки разрешения возвращается
один результат на порт с `IP == nil` и исходной ошибкой. Пустой ответ resolver
обрабатывается как отсутствие адреса. IP-литералы обходят DNS.

## Состояния и ошибки

| Значение | Условие |
| --- | --- |
| `open` | TCP-соединение установлено; пакет сразу его закрывает |
| `closed` | `ECONNREFUSED` |
| `timeout` | `context.DeadlineExceeded` или `net.Error.Timeout()` |
| `unreachable` | `ENETUNREACH`, `EHOSTUNREACH`, `ENETDOWN`, `EHOSTDOWN` или DNS `IsNotFound` |
| `canceled` | `context.Canceled` |
| `error` | прочие ошибки, включая остальные ошибки DNS |

Классификация использует `errors.Is`/`errors.As`, флаги `net.DNSError` и коды
системных ошибок, без сравнения текста. Исходная ошибка сохранена в `Err`;
для `open` она равна nil. Классификация отражает ответ ОС: фильтрация трафика
может выглядеть как таймаут, а не как явная недоступность.

`Duration` измеряет подключение, включая закрытие соединения; при ошибке DNS —
время разрешения имени. Ожидание рабочего слота и чтения результата не включается.
`Host` содержит нормализованную исходную цель; `IP` принадлежит конкретному результату.

## Конкурентность, поток и отмена

На вызов `Scan` создаются производитель заданий, не более `concurrency` рабочих
горутин и горутина закрытия результатов. Задания передаются без буфера; буфер
результатов вмещает `concurrency` элементов. Декартово произведение целей, IP и
портов в памяти не строится. Медленный читатель создаёт обратное давление:
рабочие ожидают выдачи результата, не удерживая слот подключения.

Порядок результатов не гарантируется. Без отмены выдаётся результат для каждой
уникальной комбинации цели, IP и порта (или цели и порта при ошибке DNS).
При отмене прекращается постановка заданий, активные подключения получают отмену,
соединения закрываются, рабочие завершаются и канал закрывается. Результаты,
которые уже находятся в буфере, можно дочитать. Для активных проверок результат
`canceled` отправляется, если канал готов его принять; при заполненном буфере
он может быть пропущен. Не начатые задания результатов не создают.
Дедлайн родительского context классифицируется как `timeout`.

Если читатель перестал читать, он **обязан отменить context**. Иначе поток может
ожидать читателя неограниченно. Закрытие канала не означает, что все задания
выполнены: после чтения проверяйте `ctx.Err()`. Установленное соединение остаётся
`open`, если отмена произошла уже после успешного подключения.

Один сканер можно использовать одновременно и повторно; настройки фиксированы
при создании. У разных сканеров независимые лимиты. Число рабочих горутин и
память растут с числом одновременно вызванных `Scan` и выбранным лимитом;
подбирайте его с учётом лимита файловых дескрипторов ОС. Разрешение DNS зависит
от системного resolver; внутренние операции cgo resolver могут завершаться позже
отмены вызывающего Go-кода.

## Ограничения и проверка

Только обычный TCP Connect. Нет SYN/UDP/raw sockets, определения ОС, CIDR,
обхода firewall, эксплуатации, повторных попыток и чтения баннеров.

```sh
go test -race ./...
go vet ./...
```

Тесты используют локальные TCP-соединения для IPv4 и IPv6 (IPv6 пропускается,
если недоступен), а также управляемые внутренние подстановки dial/resolver для
воспроизводимой проверки таймаутов, отмены, DNS, общего лимита конкурентности
и обратного давления. Для тестов нужен доступ к loopback; внешний интернет не нужен.
